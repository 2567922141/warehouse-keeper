# 版本更新记录

> 本文记录 Warehouse Keeper 各版本的迭代摘要，逐条改动见 Git 提交记录。
>
> 早期版本记录里提到的「网页」（网页面板、网页下单等）属于重写前的旧版本线；26.2 版本线自 0.20.0 起重写，不含网页端，相关能力只在游戏内面板与指令里提供。

### 1.3.0（当前）

> 内置 Carpet 与语音包，补齐 issue #7 / #8 的修复，并重做区域显示与取色盘。

**新增**

- **内置 Carpet**：以 Jar-in-Jar 打包 Carpet 26.3（MIT），搬运工开箱即用；mods 里另装 Carpet 时由加载器按 root 优先只保留一份，许可见 `THIRD-PARTY-NOTICES.md`。
- **内置语音取货（默认关闭）**：主体包内置 `warehouse-keeper-voice` 0.5.0，不需要另放 jar；新安装默认关闭，在 设置 → 语音取货 打开「启用语音取货」后生效（等价于 `settings.txt` 的 `enabled=on`）。识别模型仍按需下载（SenseVoice 默认约 228 MB，另有 Paraformer 小 / Zipformer-CTC / Paraformer 完整版，可从官方、魔搭、hf-mirror 或自动选源，支持断点续传与 sha256 校验）。旧的独立语音包设置文件没有 `enabled` 行时按开启迁移，原有模型、别名与 AI 配置继续有效。
- **仓库代表色**：`/warehouse region color <仓库> [颜色]`，维护页提供调色盘（色轮 + 明度条 + 六条 H/S/V/R/G/B 滑条 + 预设 + 历史）。
- **区域显示改为半透明长方体**：按代表色绘制并标注仓库名，只画同维度 128 格内的仓库；框体高度跟随仓库里实际的箱子（最低箱子往下 8 格、最高箱子往上 8 格）。
- **暂存箱入仓**：不在任何仓库范围内、且开启「暂存」的箱子，标签栏多出「仓库」下拉与「整理入仓」按钮；由值守该仓库的搬运工搬进仓库，这类箱子不计入统计、也不参与整理。
- **仓库改名**：`/warehouse region rename <旧名> <新名>` 与维护页改名输入框；搬运工正在整理该仓库时拒绝。
- **权限成员管理**：`/warehouse user add|remove <玩家名>`，`user perm` 对未登记玩家会自动建行；面板「权限」页新增玩家名输入框与「添加」按钮。
- **文案规范**：`docs/文案风格.md` 与 `scripts/copycheck.ps1`。

**变更**

- 取货库存判定：下单按「有假人值守的仓库合计」判断，派单按各假人值守仓库的实际可供应量从多到少选人；选中仓库不够时先等有货的搬运工，而不是直接失败。
- 语音侧库存预检：快照数量不足时照常下单，只在回显里提示「服务端将复核库存」。
- 玩家可见文案统一为书面语，去掉语气词与口语动词。
- 「完全调用 AI 改写」改为只走 AI：本地匹配与复判都不参与，超时/未配置/回答不合法时只提示。
- 设置页控件改为固定行高 + 滚轮翻页，窗口再小按钮也不缩水。
- 版本号：主体 1.3.0、语音 0.5.0。

**修复**

- 物品页分类下拉只有「全部分类」（物品页补发 `KIND_OVERVIEW` 查询）。
- 附加属性显示组件 ID 与 SNBT（`Variants.friendly` 兜底改为可读值）。
- 管理员提示「没有权限记录」且命令不可用（`user perm` 自动建行）。
- 取货框显示 `id@hash`（带组件变体的行改为填服务端整行名）。
- 取色盘元素重叠、色轮有台阶感（改为 256×256 烘焙贴图）。
- 容器标签栏的仓库下拉展开位置错误。
- 仓库颜色改动后不刷新（区域签名纳入颜色）。
- 整理入仓 0 秒收工（先让搬运工走近暂存箱、等区块加载；失败时给出具体原因）。

**移除**

- 地图联动（JourneyMap）整块删除。
- `SWEEP` 清扫任务的残留入口。

### 1.2.1（当前）

> 修掉 1.2.0「升级后仓库、假人、标签全没了」的迁移缺陷（改成只复制、绝不丢弃），新增附属模组设置页，并清理一批并发与索引问题。

**新增**

- **附属模组设置页**：装了 `warehouse-keeper-voice` 之类的附属包后，「设置」页会自动多出子页（「常规」+ 每个附属模组一页）。附属模组通过 entrypoint `warehouse-keeper:addon`（接口 `com.ds.warehouse.api.AddonSettings`）把自己的设置项挂进主面板；没有该 entrypoint 的旧附属包会在「常规」页下显示一行灰字提示，坏掉的附属包只记一条日志、不影响主面板。语音包 0.3.1 起用上这个入口（主/副模型、对照、并行、预加载、下载镜像）。

**问题修复**

- **升级后「仓库、假人、标签全没了」**：1.2.0 用「目录建立时间」判断旧数据目录是不是已删存档的遗留，而备份/还原出来的存档目录时间戳很新，于是把玩家真正在用的数据当成孤儿改名归档，进档后什么也没继承。1.2.1 改成：归档目录自己记着 `worldPath`，指的就是当前存档 ⇒ 当同一存档直接迁移；判不准时也不再归档，而是整套复制进存档目录，并按名字一并认领 `.orphan-*`/`.migrated-*`/`.legacy-*` 这些历史目录。
- **迁移只复制、不删除、不改名**：目标缺哪个文件就补哪个；目标比源小（1.2.0 写下的空壳）就把空壳另存 `xxx.replaced-<时间戳>` 再用真数据顶上；两边都是真数据就把源另存 `xxx.legacy-<时间戳>`；来源目录里写一份 `.migrated.json` 记下 `worldId`，同一存档不重复搬、换存档也不会混数据。
- **多个老位置同时存在时以最新的为准**：先按数据文件的最新时间排序再依次合并，更旧的快照只能另存 `.legacy-*`，不会把新数据顶掉。
- 删除仓库后区域内箱子的标签不再残留（`/warehouse region remove` 会一并清掉并在提示里报条数）。
- 局部重扫被中止时，还没扫的区域会交回增量刷新队列，稍后自动补扫，不再长期缺一块。
- 搬运工被直接移除（不是死亡）时，手里还握着的物品会被放下并记一条日志，不再卡在搬运状态。
- `regions.json` 读成空文件时不再被下一次保存直接覆盖（先另存 `.bak` 并说明原因）；`web-key.dat` 异常时会写明白为什么重建、并把旧钥另存 `.bak`。
- 索引「每 60 轮整份重算」改为「累计 2000 条容器增删才算」，长时间小改动不再周期性卡一下；索引没有变化时不再重复构建快照、重复写盘。
- 取货数量不足时不再整单拒绝，改成**有多少给多少**并在聊天栏说明差多少（例：「仓库里「X」只有 12 个，不够 32 个，本单按库存给 12 个。」）。

**升级提示**

- 替换 jar 即可，索引与配置格式未变，**不需要重新扫描**；进档时聊天栏会打印一行迁移汇总（迁移了哪些文件、多少字节、旧目录是否保留）。
- 1.2.0 已经归档到 `config/warehouse-keeper/worlds/<名称>.orphan-<时间戳>/` 的数据，1.2.1 会自动认领并复制回存档目录；如果你已手动复制回去，内容相同、不会重复。
- 旧数据目录一律原样保留（只复制），回退到旧 jar 也不会丢东西。
- **多人游戏：迁移发生在服务端**，客户端升级不影响；服务端升级前建议先备份 `config/warehouse-keeper/`。

### 1.2.0

> 仓库数据搬进存档目录，解决「删掉同名存档再新建，上一个存档的仓库数据混进来」；面板新增顶级「设置」页。

**新增**

- 仓库数据改存到 `<存档>/warehouse-keeper/`（索引、区域定义、搬运工名册、归位点、容器标签），随存档一起备份与搬迁；新增 `meta.json` 记录世界身份（随机 id + 存档路径 + 建立时间）。实例级设置（`settings.json`、`categories.json`、`players.json`、`audit.log`、客户端偏好）仍留在 `config/warehouse-keeper/`。
- 顶级「设置」页（非管理员同样可见）：容器标签栏停靠位置（自「维护」页移入）、记住上次打开的页面（默认开）、界面密度（舒适/紧凑）、界面配色（深海蓝（默认，与旧版逐字相同）/石墨/松林/暮紫，只换颜色不改布局）。

**问题修复**

- **同名存档重建后旧数据混进新存档**：以前只按「存档目录名」区分数据，删档再新建同名世界会照读上一个存档的索引、区域与标签（索引里的路径校验在同名同路径下必然通过）。现在数据跟着存档目录走；升级后第一次进档会比对「旧数据目录的建立时间」与「当前存档的建立时间」，明显更早的判为已删除存档的遗留，改名 `.orphan-<时间戳>` 归档且不加载；同一存档则复制进存档目录并把旧目录改名 `.migrated-<时间戳>`（全程只复制与改名，不删除）。
- **「物品」子页的仓库列表占满上半部分**：该子页被强制单栏、仓库列表被拉成整宽横条，与其他子页结构不一致；现在恢复两栏，仓库列表固定留在左上角，物品清单进右栏。
- **新存档无仓库时的引导文字被截断**：列表里只留一行「还没有仓库」，四行引导改画在右侧空白处；极窄的单栏模式不画（底部仍有完整说明）。

**升级提示**

- 替换 jar 即可，索引与配置格式未变，**不需要重新扫描**；服务端与客户端都要升到 1.2.0（数据位置在服务端，面板与设置在客户端）。
- 若你以前删过某个存档、之后又新建过同名存档，那份旧数据会被判为孤儿归档 ⇒ 进档后面板显示「还没有仓库」，重新 `/warehouse scan <仓库>` 即可；想保留那份数据，先把 `config/warehouse-keeper/worlds/<存档名>/` 里的文件复制进 `<存档>/warehouse-keeper/`。
- 回滚：换回 1.1.6 jar；旧数据目录仍在原处（被改名为 `.migrated-`/`.orphan-`），需要时手动复制回去。

### 1.1.5

> 修复复审发现的取货语义与挥手动画问题。功能、指令与配置与 1.1.4 一致。

**问题修复**

- **跨仓库取货可能少拿却记成「已送达」**：库存校验原来用的是**全仓合计**，而实际取货只从「假人值守的那一间仓库」里取 —— A 仓 10 个（有假人值守）、B 仓 100 个（没假人）时下单 50 会被放行，实际只交付 10 个并记为已送达。现在下单时按**有人值守的仓库**分别校验（不足则明确拒绝，并提示给货多的仓库指派假人），派单时再按该假人值守的仓库复核一次；「仓库中仅剩 N 个」的说明也不再被交货提示覆盖。
- **搬运工挥手多收一个自己的动画包**：26.3 的 `swing` 第三参是 `sendToSwingingEntity`，1.1.4 传了 `true`；javap 复核 26.2 的单参数版本转发的是 `false`，已改回 `false`，与 1.1.3 严格等价。
- **面板取货数量填了非数字会静默按 1 个下单**：现在明确提示「数量请填 1~4096 的整数」并且不下单。

**升级提示**

- 替换 `mods/` 里的旧 jar 即可；索引、配置、仓库定义、标签、权限与审计全部沿用，不需要重新扫描。
- 服务端与客户端都要换成 1.1.5（跨仓库校验在服务端执行，只升客户端不生效）。

### 1.1.4

> 正式适配 Minecraft 26.3（「奔赴荒野」，2026/09/15）。除下面列出的行为订正外，功能、指令、索引格式与配置文件与 1.1.3 一致。

**适配与修复**

- **窗口与输入层换成 SDL3**：26.3 用 SDL3 取代 GLFW，`org.lwjgl.glfw` 不再可用；按键注册改用 `InputConstants.Type.KEYBOARD` + `InputConstants.KEY_B`。默认按键与键位设置行为不变。
- **`LivingEntity.swing` 签名变化**：26.3 为 `swing(InteractionHand, SwingAnimation, boolean)`，搬运工挥手传 `SwingAnimation.DEFAULT` 与 `false`；javap 复核 26.2 的单参数版本转发的是 `false`，因此与 1.1.3 行为一致。
- **`Inventory.placeItemBackInInventory` 增加预测参数**：搬运工在服务端执行，使用 `Prediction.SERVER_ONLY`。
- **依赖约束更新**：`minecraft` 约束由 `~26.2` 改为 `~26.3`；Fabric Loader 0.19.5 与 Fabric API 0.161.0+26.3 实测通过。
- **取货数量超上限时不再静默截断**：面板、指令与语音下单的数量超过 4096 时，1.1.3 会静默按 4096 处理；现在改为明确提示「一次最多下单 4096 个」并且**不下单**，与服务端 `Porter.MAX_ORDER` 的判定一致。

**存档及模组升级提示**

- **存档升级不可逆**：26.3 的 `DataVersion` 从 4903 升到 5023，存档一旦在 26.3 里保存就无法再用 26.2 打开，升级前请备份 `saves/`。
- 已探索区块不会重生成，新区块按 26.3 的新世界生成算法产生，边界可能有接缝；数据包/资源包格式从 107.1/88 跳到 121.0/97.1。
- 服务端与客户端都要换成 1.1.4；索引、仓库定义、标签、权限与审计原样沿用，不需要重新扫描。
- 存档里若用了更多箱子，其方块与物品在 26.3 会消失（对应索引条目减少）；等它出了 26.3 版本再补回来并重扫一次即可。

### 1.1.3

> 来自 10/6 实机反馈（issue #4）：多人游戏下客户端取货页的分类下拉只剩「全部分类」和「其他」；以及假人算一个玩家，假人多了真人反而进不来。

> V1.1.3是目前最后一个适配 Minecraft 26.2的新版本，从V1.1.4版本起，mod主要适配Minecraft 26.3。

**问题修复**

- **多人游戏下客户端取货页分类只剩「全部分类 / 其他」**：分类以前是客户端现算的（要「物品 → 创造模式页签」那张表，而那张表只有服务端建得起来），访客（连专用服的玩家、局域网客人）进程里没有服务端，于是每件物品都被算成「其他」——单机与房主一直正常，所以报告里才写「有时」。现在服务端在建索引时就把类目键算好、随快照逐行下发（字段 `category`），面板优先用它；分类候选的顺序也改成「服务端下发的类目清单 → 本机页签注册表 → 旧版清单」三级回落。顺带修掉两个会让「按分类筛选」一件都筛不出来的坑：快照字段名与客户端字段名不一致（Gson 按字段名对拷），以及「全部仓库」范围下的合并行漏拷类目。
- **搬运工占玩家名额**：搬运工是 Carpet `/player` 生成的真正服务器玩家，原版满员判定数的是「所有在线玩家」，于是名册里放几个搬运工就等于占几个名额，假人一多真人就只能看到「服务器已满」。现在新增一处很小的 Mixin，只把**本模组名册里的**搬运工从满员计数里剔掉；封禁、IP 封禁、白名单、重复登录与 OP 免限检查一个没动，`max-players` 也不用改。注入点带 `require = 0`，将来原版代码变动导致对不上时只会静默退回原版行为，不会崩服。

**升级提示**

- 本版**没有改动索引格式、配置文件与指令语法**：替换 jar 即可，已有仓库定义、标签、权限、审计与索引都能直接沿用，不需要重新扫描。
- **联机时服务端要一起升到 1.1.3**：分类键由服务端下发，只升客户端会出现「分类名是真的、但筛出来是 0 件」。
- 「搬运工不占名额」只需**服务端**装 1.1.3（单机与局域网房主的客户端本身就是服务端）。
- 界面截图见 `photo/image-5.png`（分类下拉里的真实类目）与 `photo/image-6.png`（选「建筑方块」后筛出的物品）。

### 1.1.2

> 来自 10/5 实机反馈（issue #3「10.5问题总结」）：取货取错物品、工作方块界面标签栏压住物品栏、显示名不同步、头顶名牌不更新四项，外加「取货页按分类筛选」这个新需求。

**问题修复**

- **取货取到名字相似的物品**：物品名解析原来是「id 精确 + 子串包含」，中文永远不是合法 id，于是只剩子串分支、再按**库存最多**挑一个 —— 仓库里没有「石头」时，剩下的唯一候选就成了「平滑石头」。现在改成三段：**id 精确 → 名字精确（唯一才认）→ 子串包含（唯一才认）**；命中多种一律拒绝并按库存从多到少列出候选（最多 10 条，附可直接复制使用的 id）；输入本身是合法物品 id 但仓库里没有（例如 `stone`，而索引里只有 `smooth_stone`）时直接回「仓库中没有这件物品」。面板取货与 `/warehouse order` 同源，`/warehouse find` 的既有行为不变。
- **工作方块界面里标签栏压住物品栏**：工作台、熔炉、高炉、烟熏炉等带配方书的界面（`AbstractRecipeBookScreen`）打开配方书时原版会把界面右移，而本模组拿不到真实几何，按「界面居中」估算出的竖栏正好落在被右移的物品栏上。现在这类界面**不再显示容器标签栏**；开箱子、木桶、铁砧等照旧显示，位置与点击都不受影响。
- **改完显示名面板先报成功、别人却看不到**：面板输入框上限 32 与服务端 24 不一致，写长了会被服务端拒绝，而按钮已经先写了成功文案。现在上限对齐 24，并在本地先拦掉换行、制表符、控制字符与颜色代码 `§`；按钮提示改为「已发送：…」，成功与否以状态栏里服务端回执为准。
- **改完显示名，假人头顶名牌仍是原始编号**：原版玩家名牌 = 记分板队伍装饰 + 档案名，`setCustomName` 对玩家完全无效。本版新增一处**纯客户端**的渲染替换（注入 `Player.getDisplayName`）：装了本模组的客户端里，名牌会显示面板里设的显示名。服务端零改动、不写存档、不生成实体、不发新数据包。
- **取货页清单受「物品」页搜索词影响**：取货页原来复用「物品」页的取数口，会被那一页搜索框里的字过滤掉一部分；现在直接读快照，只受取货页自己的筛选框 + 仓库 + 分类控制。

**新功能（取货页按分类筛选）**

- 筛选行变成「筛选框 | 分类 ▾ | 仓库 ▾」三件套，分类下拉与仓库下拉是同一套实现（展开、滚动、点选、滚动条一致）；候选按当前取货范围里**实际存在**的物品现算，顺序照创造栏页签顺序，不会出现空分类，超过 8 条自动出现滑块与「a~b / n」计数。
- 清单、标题里的「共 N 种物品」、点一行填入取货框、滚轮上限都跟着分类一起筛，表头显示「（分类：xxx）」。切换仓库时按分类**键**保住选中项，那一类在新范围里不存在才回到「全部分类」。
- 三个控件的宽度按行宽计算，窗口再窄也会依次收缩（分类按钮 → 仓库按钮 → 筛选框），不会互相压住。

**升级提示**

- 本版**没有改动索引格式、配置文件与指令语法**：替换 jar 即可，已有仓库定义、标签、权限、审计与索引都能沿用，不需要重新扫描。联机时服务端与客户端版本需一致，显示名的「头顶名牌替换」只在装了 1.1.2 客户端的那一侧生效。

### 1.1.1

> 来自 10/4 多人联机实测反馈：一是「部分数据更新不及时」，二是「一个仓库希望多个搬运工同时整理」。

**问题修复（多人游戏数据更新不及时）**

- **标签栏类目对不上**：类目表原来只在服务端进程里生成，非房主（访客）进程拿不到页签表，下拉会退化成旧版类目名，看起来就是「新版本标签同步不过来」。现在类目表随仓库快照一起下发，客户端再按「服务端快照 → 本地顺序 → 页签注册表 → 旧版清单」四级回落，两边显示一致；房主新贴的类目也会同步到其他客户端。
- **空闲后的第一次变化要等约 1 秒**：空闲冷却原来会把时钟重置成慢档，现在立即按快节奏推送。
- **假人收回/放出、整理进度变化不推送**：快照指纹补齐「在不在岗」与「整理进度档」两项。
- **漏收的玩家要等下次变化才补**：新增补发名单，未送达者在 60 秒内重试，不再卡在旧数据上。
- **超大快照全服静默不发**：标签数量单独设上限（4000），超限不再拖垮整份快照，并在 `/warehouse status` 里显示「待补发人数 / 过大跳过次数」。
- **`/warehouse categories reload` 不刷新缓存**：现在同时作废类目缓存、创造模式页签顺序与网页快照。
- **管理员推中文物品名后，普通玩家游戏内不更新**：网页快照与游戏内快照现在都会跟着刷新。
- **组包失败会静默停更**：改成组包成功后才记账，失败记日志并在下一轮重试。

**体验优化（一个仓库多个搬运工）**

- `/warehouse porter tidy <仓库>`（与面板上的整理按钮）现在把该仓库在场的**所有**搬运工编成一组，按箱子哈希把箱子分片给每人，各片互不重叠；有人中途退出或被收回时自动按实际人数重摊。
- 进度列显示「本片 a/b 箱 · 全仓 x/y 箱」，名册「在忙什么」列能直接看出谁管哪一片。
- `/warehouse porter staff <仓库>` 不再「已经有搬运工就挡回」，会继续补人并提示该仓库现有几名。
- 整理途中换箱立即释放认领，同伴不必等前一人整轮干完。

**顺手修掉的隐患**

- 容器界面标签栏的「双联箱兜底」收窄为「原版箱子 / 带箱子 TYPE 属性的模组箱子」，木桶、潜影盒等永不成对的容器不再显示邻居的标签。
- 整理顺序或类目注册表里出现异常条目时跳过该条，不再中断整轮任务。
