# Warehouse Keeper v1.2.0

数据位置与界面更新版。这一版把仓库数据从游戏实例的配置目录**搬进存档目录内部**，解决「删掉同名存档再新建一个世界，上一个存档的仓库数据混进来」；面板新增顶级「设置」页（标签栏位置、记住上次打开的页面、界面密度、四套界面配色），并修掉「物品」子页两栏结构不统一与空仓库引导文字被截断。**索引格式、配置文件与指令语法均未改动**。

| 项目 | 说明 |
| --- | --- |
| 适配 | Minecraft **26.3** · Fabric Loader **0.19.5**（0.19.3+） · Fabric API **0.161.0+26.3** · Java **25** |
| 可选依赖 | Carpet 26.3（安装后搬运工以可见人形出现；不装也能正常取货/整理） |
| 文件 | `warehouse-keeper-1.2.0.jar`（491,093 B） |
| SHA-256 | `2402346ec09bc1b1a3f0cc2028ed3f299df4eb191010286f942822fd3facbe94` |

> 本版本**没有改动索引格式、配置文件与指令语法**：升级只需替换 jar，仓库定义、标签、权限、审计与索引都能沿用；数据会随升级自动搬进存档目录，**不需要重新扫描**。

## ✨ 新增

### 仓库数据改为写在存档目录内部

以前「哪个存档的仓库数据」只按**存档目录名**区分，数据放在实例的 `config/warehouse-keeper/worlds/<存档名>/` 下。删掉一个存档、再新建一个默认同名（例如「新的世界」）的世界时，存档路径完全相同，模组会照读上一个存档的索引、区域、搬运工名册与容器标签 —— 也就是数据串档。

现在：

```
saves/<存档名>/warehouse-keeper/
├── meta.json             世界身份：随机 id、存档路径、建立时间
├── index.json            仓库索引
├── regions.json          仓库区域定义
├── bots.json             搬运工名册
├── homes.json            搬运工值守/归位点
└── container-tags.json   容器标签
```

- **数据跟着存档走**：备份、复制、搬迁存档会一起带走仓库数据；换一台机器、换一个启动器实例，只要带的是同一份存档目录，面板里的仓库和索引就还在。
- **`meta.json` 里的随机 id 是世界身份**：世界被改名或移动时只更新记录里的路径，id 不变，数据仍然对得上。
- 实例级文件（`settings.json`、`categories.json`、`players.json`、`audit.log`、客户端偏好）仍留在 `config/warehouse-keeper/`，不随存档走。

**旧数据怎么处理**（升级后第一次进档时自动完成，全程只复制与改名、**不删除**）：

| 情况 | 处理 |
| --- | --- |
| 同一存档（正常升级、世界改名/移动、备份还原） | 把 5 份数据文件**复制**进 `<存档>/warehouse-keeper/`，旧目录改名为 `worlds/<存档名>.migrated-<时间戳>` |
| 旧数据目录建立时间**明显早于**当前存档（>5 秒容差） | 判定为**已删除存档的遗留**（删档再建同名存档的情形）：旧目录改名为 `worlds/<存档名>.orphan-<时间戳>`，**不加载、不继承** |
| 存档目录不可写 | 退回旧的 `config/warehouse-keeper/worlds/<存档名>/` 位置并在日志里说明 |

### 面板新增顶级「设置」页

一级页签新增「设置」（非管理员同样可见），四行开关都是**客户端偏好，只影响本机**：

- **容器标签栏停靠位置**：自动 / 左 / 右 / 上 / 下（自「维护」页移入）。
- **记住上次打开的页面**（默认开）：关掉后每次打开面板都回到「仓库 · 概览」。
- **界面密度**：舒适（默认，与旧版一致）/ 紧凑。只改边距、行高与间距，布局与信息量不变，适合小窗口或想一屏看更多。
- **界面配色**：深海蓝（默认，**每个颜色值都与旧版逐字相同**）/ 石墨 / 松林 / 暮紫。四套主题只换颜色、不改布局；面板与容器标签栏共用同一套配色，切换后立即生效。

## 🐛 问题修复

- **删掉存档再新建同名存档，上一个存档的仓库数据混进来**：根因与处理见上「仓库数据改为写在存档目录内部」。删除存档后再新建同名世界，现在会走「孤儿归档」路径：旧数据改名保留但不加载，面板是干净的「还没有仓库」。

- **「物品」子页的仓库列表占满上半部分**：该子页以前被强制单栏，仓库列表被拉成整宽横条，与其他子页（概览/新建/扩建缩小/箱子/维护）结构不一致。现在恢复两栏：仓库列表固定留在左上角，物品清单进右栏；窗口过窄时仍按同一规则整体降级为单栏。

- **新存档里没有仓库时，引导文字被挤在窄列表框里截断**：以前把「还没有仓库 / 站到一角 → 点1 / 再站到对角 → 点2 / 填写名字 → 新建仓库」四行画在窄列表框中，文字会被裁掉。现在列表里只保留一行「还没有仓库」，四行引导画在右侧空白处；极窄的单栏模式不画引导（底部「最近结果」仍有完整说明）。

## ⬆️ 升级提示

- **替换即可**：删除 `mods/` 里的旧 `warehouse-keeper-*.jar`，换成 `warehouse-keeper-1.2.0.jar`。不要同时留下新旧两个 jar（同一模组 ID 会导致加载失败）。
- **服务端与客户端都要升到 1.2.0**：数据位置改动在服务端，面板与「设置」页在客户端。
- **进档前请知悉**：如果你曾删掉某个存档、之后又新建过同名存档，那份旧数据会被判为孤儿并改名归档 —— 进档后面板会显示「还没有仓库」，重新 `/warehouse scan <仓库>` 即可重建。**想保留那份旧数据**，就先把 `config/warehouse-keeper/worlds/<存档名>/` 里的 5 个文件复制到 `<存档>/warehouse-keeper/`（该目录不存在就新建）。
- **想回滚到 1.1.6**：换回旧 jar 即可。1.2.0 期间的数据写在存档目录里，旧位置的数据目录被改名为 `.migrated-<时间戳>`（或新建存档时是 `.orphan-<时间戳>`）**仍在原处**，需要时手动复制回去。
- 升级后建议验证一次：① 进档后 `/warehouse status` 能看到原有仓库与索引（数据已跟过来）；②「设置」页四个开关都能立刻生效、切颜色后容器标签栏同步换色；③ 打开「物品」子页，仓库列表在左上角、物品清单在右侧。

## ⚠️ 已知限制

- **存档目录里会多一个 `warehouse-keeper/` 子目录**（几十 KB 到几百 KB）：这是数据存放位置；分享或上传存档时会连带带上仓库数据（含箱子坐标与容器标签），不需要的话删掉该目录即可（面板会变成「还没有仓库」，重新扫描可重建）。
- 索引的后台保存失败只写日志（`后台保存索引失败: …`），不再主动弹给玩家；需要当面确认成败时用 `/warehouse save`。
- RCON/指令与面板的取货上限仍是 4096；超限与非法输入都明确拒绝，不静默截断。
- 更多箱子（Iron Chests）暂无 26.3 版本，26.3 上**尚未实测**（26.2 版本线正常）；存档里若用过它，其方块与物品在 26.3 会消失。
- 未安装 Carpet 时搬运工不可见，仅能通过指令与面板观察作业结果。
- 专用服务端在没有客户端连入时，指令输出中的物品名为英文。
- 中文物品名依赖客户端向服务端推送名称表；原版 26.3 新增物品若客户端解析不出中文名，会退回显示物品 id（可在面板里按 id 搜索与取货）。
