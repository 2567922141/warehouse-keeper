# 玩家可见文案风格

本文约束两个模组（`warehouse-keeper` 与 `warehouse-keeper-voice`）里**玩家能看到、听到的所有文字**：
聊天回显、界面按钮与提示、状态栏、标题、错误说明、语音播报。代码注释与日志不受本文约束。

## 1. 总体要求

- 使用书面、正式的表达，像一份简短的操作说明，而不是聊天。
- 一句话说清「发生了什么 + 现在能做什么」，不做寒暄，不用语气词。
- 能省的字要省：短句优先于长句，不重复同一信息。
- 不保证成功的事不要写成保证；尚未发生的事用「将」「会」并说明前提。

## 2. 称呼与主语

- 对玩家称「你」，不用「您」「玩家您」。
- 系统自身用「本模组」「仓库」「面板」，不用「我们」「这边」。
- 具体对象用「「名称」」包起来，如「圆石」「一楼仓库」。

## 3. 句式模板

| 场景 | 写法 |
| --- | --- |
| 操作成功 | `已完成 X。` / `已下单 N 个「X」。使用 /warehouse porter 查看进度。` |
| 部分成功 | `已完成 X；另有 N 项未处理：…` |
| 操作失败 | `无法 X：原因。请…` |
| 前置条件不足 | `X 尚未 Y，请先 Z。` |
| 进度 | `正在 X（N/M）。` |
| 提示补充 | 用括号，一句话：`（本地快照为 N 个，服务端将复核）` |
| 引用命令 | 命令原样写出，如 `/warehouse user add <玩家名>` |

错误提示必须包含**可执行的办法**；不能只写「失败」「没有权限」。

## 4. 数量、单位与数字

- 数量写阿拉伯数字，单位紧跟：`44 个`、`3 组`、`2 只箱子`。
- 范围用 `1~4096`（波浪号，两侧不留空格）。
- 分数数量词写作 `四分之一组`，回显折算后的个数。
- 坐标写作 `x y z`，如 `-78 90 -26`。

## 5. 禁用词与写法

- 不用语气词：呢、吧、哦、啦、哟、呀、嘛、嘿、哈、咦、诶、哎。
- 不用口语动词与短语：点一下、点这里、没法、弄死、稍等、先别、搞定、凑合、咱们、一下下、真的删掉。
- 不用感叹号（`！`）与波浪号装饰（`~` 只用于范围）。
- 不用「哦」「嗯」这类应答词开头。
- 不出现内部实现名：组件 ID（如 `quality`）、SNBT、类名、线程名。

## 6. 界面控件的文字

- 按钮用动词或名词短语，2~6 个字：`添加`、`改名`、`整理入仓`、`保存并应用`。
- 开关统一「开 / 关」，不用「启用中」「已关闭」。
- 占位符说明输入内容：`玩家名（可中文）`、`新仓库名（可中文）`。
- 不可点的控件要在悬停提示里写明原因与前提。

## 7. 语音回显

- 语音侧回显与聊天命令保持同一套句式，尽量一行说完。
- 识别失败与库存不足都要给出下一步：改口再说、打开面板、等待搬运工、联系管理员。

## 8. 校验

改动文案后运行：

```powershell
pwsh -File scripts/copycheck.ps1
```

脚本扫描两个仓库 `src/main/java` 下字符串字面量里的禁用词与感叹号，命中时列出 `文件:行: 命中词` 并返回退出码 1。
语音识别用的同义词典（`VoiceText.java` 的词表）属于数据，不在扫描范围内。
