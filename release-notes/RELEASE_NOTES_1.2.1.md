# Warehouse Keeper v1.2.1

旧存档数据全量迁移版，并加入附属模组设置页。1.2.0 把仓库数据搬进存档目录时，用「目录建立时间」判断老数据是不是**已删存档的遗留**：存档目录比老数据目录**晚**建立 5 秒以上就判成遗留，整份改名归档、不继承。备份还原、改过名、从别处拷回来的存档都会踩中这条 —— 进档后仓库、区域、搬运工名册、容器标签全空（**数据还在磁盘上，只是没被读**）。这一版把这条判据从「猜」改成「认」：老位置的数据**一律全部搬进存档目录**，只做复制，不再有「判成遗留就不继承」这条路。

## 🐛 修复：升级后仓库与搬运工全空

**现象**：从 1.1.6 升级到 1.2.0 后，进老存档看到「还没有仓库」、搬运工不见、之前建的仓库没了；进多人游戏同样。

**根因**：1.2.0 的判定表里，「同一存档」与「已删存档的遗留」只靠**目录建立时间**区分：

| 旧判据（1.2.0） | 结果 |
| --- | --- |
| 老数据目录建立时间 + 5 秒 < 存档目录建立时间 | 判为遗留 ⇒ 改名 `worlds/<存档名>.orphan-<时间戳>`，**不加载、不继承** |
| 其余 | 复制进存档目录，老目录改名 `.migrated-<时间戳>` |

存档被**备份还原**过、**改过名**、**从别的机器拷回来**，或存档目录是新建同名世界时，其目录建立时间都会晚于老数据目录 ⇒ 误判成遗留 ⇒ 面板全空。数据其实一个字节都没少，只是被归了档。

## ✨ 1.2.1 的迁移规则（进档时自动执行）

| 情况 | 处理 |
| --- | --- |
| 存档内没有该文件 | 复制进 `<存档>/warehouse-keeper/`（`COPIED`） |
| 两边字节完全相同 | 什么都不做（`SAME`，可反复进档） |
| 存档内的文件**比老位置小**（典型是 1.2.0 刚建出来的 402 B 空索引、186 B 占位名册），且这个文件名还没被更新的来源处理过 | 老数据顶上，**旧的那份另存** `<名字>.replaced-<时间戳>`（`REPLACED`） |
| 两边都像真数据（存档内那份不小于老位置但内容不同），或这个文件已由更新的来源处理过 | 存档内那份**不动**，老的那份另存 `<名字>.legacy-<时间戳>`（`KEPT_BOTH`） |
| 老目录看起来属于**另一个**世界，且它记录的 worldPath 不指向当前存档 | 迁到存档内 `legacy-<时间戳>/` 子目录隔离，不动当前存档的数据 |

要点：

- **老位置永远保留完整一份**：迁移只做复制，**不删除、不改名老目录、不覆盖任何文件** —— 任何被替换/保留的文件都另存一份带时间戳的副本，两边都不会丢。
- **不再只认 5 个固定文件名**：老目录下的文件按同名全部搬过去，子目录保留结构；名字以 `.migrated` 开头的标记文件除外。
- **自动认领历史归档**：以前被 1.2.0 改名成 `worlds/<存档名>.orphan-*`、`.migrated-*`、`.legacy-*` 的目录都会被重新扫描（按存档名前缀匹配），里面的数据会被正常搬进存档目录。
- **多个老位置同时存在时以最新的为准**：老位置往往不止一个（现役目录 + 1.2.0 归档的 `*.orphan-*`）。迁移按「老目录里最新数据文件的修改时间」把来源排成最新在前，**同一个文件名只由最新的来源决定「顶掉空壳」还是「另存保留」**；更旧（哪怕字节更多）的归档只会被另存为 `.legacy-*`，不会反过来压住更新的数据。
- **不再靠目录时间来猜**：新判据是「老目录里最新数据文件的修改时间**早于**当前存档目录建立 5 秒以上」**且**「老目录记录的 `worldPath` 不指向当前存档」两条同时成立，才当作外来数据隔离。备份还原、改名、移动存档等情况下 worldPath 对得上（老位置记录的路径就是当前存档路径），一律正常迁入。
- **`meta.json` 优先采用老位置的**：存档内还没有 meta.json 时先沿用老位置的 worldId，避免同一份存档在升级过程中换 id。
- **`.migrated.json` 标记**：每次迁移成功后写进老目录，记录这份数据已经迁进哪个 worldId。同一存档反复进档不会重复搬；换存档（worldId 不同）不会把上一份数据混进来。
- **迁移结果会说明**：逐份写进日志（info/warn），并在进档时于聊天栏汇总一行（例如「仓库数据迁移：5 个文件，新迁入 3，替换空壳 2，共 168,608 字节」）。

## 🧩 新 API：附属模组设置页

主面板的「设置」页现在可以是多页：**「常规」+ 每个附属模组一页**。

- 附属模组实现 `com.ds.warehouse.api.AddonSettings`（`id()` / `title()` / `summary()` / `rows()`），在 `fabric.mod.json` 里声明自定义 entrypoint `warehouse-keeper:addon` 即可挂进来。
- 每行是 `label / value / note / kind / enabled / act`，`kind` 取 `CYCLE`（点一下换一个值）、`TOGGLE`（开关）、`TEXT`（**输入框**：1.2.1 起主体的面板把它画成真的 EditBox，`value` 只当占位提示，回车 / 换页 / 关面板回调 `Row.text(String)`；`Row.secret()` 为真的行显示星号，只回显前 4 位）、`INFO`（只显示不占按钮）。附件 `api/SimpleRow` 提供现成的静态工厂，附属包不必自己实现行类型。
- 附属包自己读数、自己写自己的配置文件：`rows()` **每次打开界面都会重新调用**，读到的就是最新值（不会拿到缓存）。
- 坏掉的附属包只写一条 warn 日志、那一页不出现，**不影响主面板**；声明了 mod id 但没提供 entrypoint 的老附属包，会在「常规」页下显示一行灰字提示。
- 语音包 **0.3.1** 起用上这个入口：主模型、副模型、对照显示、并行识别、预加载模型、下载镜像都能在主面板「设置 → 语音取货」里改。
- **1.2.1 又加了分区标题与下拉**：附属包可以把设置项按功能分组（`SimpleRow.header("识别模型")`），需要从多个值里挑的行改成一个**真下拉菜单**（`SimpleRow.choice(label, options, index, note, picker)`，点开挑选、选中打 ✓、Esc 只收下拉）；老附属包不受影响（新增的都是 `default` 方法，老主体上 `choice` 行会自动退化成「点一下换下一个」）。

## 🧩 同 id 不同数据的物品终于能分开了（组件变体）

药水、地图、染色装备、烟花、成书这类物品**共用同一个 id**，以前索引按 id 合并，只能看到「药水 x12」——是哪一种、点哪一行取的都可能是随机一瓶。1.2.1 起按**组件**分行：

- 索引里每件物品多一维 `variantKey` = 物品 id + 规范化组件摘要（如 `minecraft:potion@1a2b3c4d5e`）；没有组件差异的物品键就等于 id，行为与以前完全一样。
- 面板「物品」页、`/warehouse list`、`/warehouse find <id>` 都会逐种列出；名字用**真实 ItemStack** 取（「抗火药水」而不是「药水」），再缀上组件注解（时长、地图编号等）。
- **「全部仓库」视图也按变体分行**（1.2.1 补漏）：这个视图跨仓库合并同种物品时，以前只按 id 合并，烟花飞行 2 秒 / 3 秒、迟缓药水 / 强化迟缓药水会被并成一行（看着像只有一种，点它取货也可能拿到同 id 的任意一种）。现在合并键优先用变体键、合并行也带着变体键，逐种分行、点哪行取哪行。
- 取货：点哪一行取哪一行（面板行里带的就是变体键），`/warehouse order minecraft:potion@1a2b3c4d5e 1` 也能直接指定；`<物品>#<附魔>` 的老写法保留，两者可以叠加。
- **不会替你猜**：用中文名（如「药水」）下单而仓库里有多种时，会列出候选让你指名；用**精确 id** 下单仍然保持老语义（哪种都行），命令与网页脚本不受影响。
- 顺带修掉「重启后药水/烟花/旗帜的组件信息全丢」：索引落盘多存一个 `comp` 字段（老索引文件照旧能读，格式号不变）。
- 语音附属包的变体支持放在 0.4.0，本版不动语音。

## 🧭 设置页按功能分区 + 下拉选择 + 连通性自检（配语音包 0.4.0）

语音包的设置页现在按功能分成几块（识别模型 / 识别方式 / 模型下载 / AI 功能；AI 页再分 服务凭据 / 连通性 / 用量），每块一行**暗底亮字的标题**加一条细分隔线；主模型、副模型、下载源、AI 服务从「点一下换下一个」改成**下拉菜单**（点开挑选、选中打 ✓）。

AI 页新增「**测试连通性**」：填完地址与 Key 想确认通不通，点一下就会在后台发一个 ping，状态行给出结果与延迟（例 `通 · 312 ms`，失败给 `Key 无效或没权限（HTTP 401）` / `超时（超过 1000 毫秒）` / `连不上：ConnectException`），**不占 AI 额度、不写统计**，也不会因为测试失败就把开关关掉。

## 🏷️ 物品属性显示成人话

带组件的物品（药水、附魔书、烟花、染色皮革、成书……）以前在仓库列表里显示的是原始数据
（`药水: {potion:"minecraft:slow_falling"}`、`附魔书: ItemEnchantments{…}`），现在改成中文逐项列出：

- 药水 → 「缓降药水」这类名字；附魔 → 「深海探索者 III」；烟花 → 「飞行时间 2 · 爆炸 小型球」；染色 → 「染色 #A06540」
- 认不出来的组件只显示中文标签，不吐 id、不吐原始 NBT；最多列 6 项
- 同一件物品的不同属性仍然分成不同条目（1.2.1 的组件变体），现在能一眼看出差在哪
- 药水、药水箭这类「有默认组件」的物品不再显示成「不可合成的药水」
- **药水会写清「哪一瓶 + 效果 + 等级 + 时长」**，例如「迟缓药水 · 缓慢 IV 0:20」；普通 / 延长 / 强化（`slowness` / `long_slowness` / `strong_slowness`）以及自定义时长都各成一条，不会混在一起
- **喷溅 / 滞留 / 药箭会写出来**：行名已经带了「喷溅型 / 滞留型 / 迟缓之箭」就不重复，行名只有「药水」时会补一个前缀
- 只有自定义效果、没有注册药水的那种药水，行名退回物品基础名（药水 / 喷溅药水），不再出现「不可合成的药水」占位符；自定义颜色会显示 `颜色 #RRGGBB`

顺带修掉一个更根子的毛病：读档时组件解码没带注册表，**附魔书这类要在注册表里查的组件读回来就丢了**
（表现是重启后附魔书变成空白）。现在落盘与读回都走带注册表的解码。

## 🧩 附属模组设置页支持「动作行」与动态行数

- 接口新增 `Kind.ACTION`（点一下做一件事）与 `SimpleRow.action(...)`；设置页行数不再写死 6 行

## ⌨️ 附属设置页能直接收文字（API Key 这类）

- 接口新增 `Row.text(String)`（default 方法，附属模组不实现也不报错）与 `Row.secret()`；
  `SimpleRow.text(label,value,note,setter)` / `SimpleRow.secret(...)` 是要 setter 的工厂，原来两个只读工厂保留。
- 面板把 `TEXT` 行画成真的输入框：实例按「附属 id + 行名」跨面板自动重建缓存，所以打字不会被打断；

- 敏感行（`secret()`）显示成星号，只保留前 4 位；改 / 清空由附属模组自己给一行按钮，避免点一下输入框又点走就把已存的 Key 洗掉。
- 每行说明改成两色显示（名称亮、说明暗），长说明不再糊成一条灰墙；语音包 0.4.0 的「设置 → 语音取货」据此分成三页，AI 页可直接填 API Key。
## 🔧 一并修掉的问题

- **删除仓库后区域内的箱子标签残留**：`/warehouse region remove` 现在会同时清掉该区域内所有容器标签，并在提示里报清掉几条。
- **局部重扫被中止后索引长期缺一块**：扫描中止时，还没扫到的区域会交回增量刷新队列，稍后自动补扫。

- **`web-key.dat` 静默换钥**：重建时会写清楚为什么（读不出来 / 长度不对）、把旧钥另存 `.bak`，并在旧网页账号库缺失时也给一条提示。

## 📌 升级与回退

- 从 **1.1.6** 或 **1.2.0** 直接替换 jar 即可，无需其它操作。
- 如果你的数据已经被 1.2.0 归档过：**装 1.2.1 后进一次档就会自动认领**。也可以手动把 `config/warehouse-keeper/worlds/<存档名>.orphan-<时间戳>/` 里的文件复制进 `saves/<存档名>/warehouse-keeper/`。
- **多人游戏**：迁移发生在**服务器**上。服务器装 1.2.0 被归档的数据，需要服务器升级到 1.2.1（或手动把服务器上的 `.orphan-*` 目录复制回去）；客户端回退版本对服务器上的数据无效。
- 想退回 1.1.6：存档目录里的 `warehouse-keeper/` 可以留着不管（1.1.6 只读 `config/warehouse-keeper/worlds/<存档名>/`），老位置的数据这份也仍然完整，两边都能跑。
