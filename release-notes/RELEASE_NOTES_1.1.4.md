# Warehouse Keeper v1.1.4

适配 Minecraft **26.3**（「奔赴荒野」，2026/09/15 发布）的平台迁移版。功能、指令、索引格式、配置文件与指令语法**与 1.1.3 完全一致**，这一版只做版本适配。

## 🔧 适配内容

- **窗口 / 输入层换成 SDL3**：26.3 把 GLFW 换成了 SDL3，`org.lwjgl.glfw` 不再可用。按键注册改用 `InputConstants.Type.KEYBOARD` 与 `InputConstants.KEY_B`（原来是 `Type.KEYSYM` + `GLFW.GLFW_KEY_B`）。默认按键、键位设置里的条目与行为都不变。
- **`LivingEntity.swing` 签名变化**：26.3 改成 `swing(InteractionHand, SwingAnimation, boolean)`。搬运工挥手改为传入 `SwingAnimation.DEFAULT` 与 `true`，与 26.2 的单参数 `swing(hand)`（内部就是转发到 `swing(hand, true)`）语义一致，不会挥得快慢不一。
- **`Inventory.placeItemBackInInventory` 增加预测参数**：26.3 改签名并引入 `net.minecraft.util.Prediction`。搬运工在**服务端**执行，因此使用 `Prediction.SERVER_ONLY`（`PREDICTED` 是客户端预测专用）。
- **依赖约束更新**：`fabric.mod.json` 的 `minecraft` 约束由 `~26.2` 改为 `~26.3`；`fabricloader >=0.19.3` 与 `java >=25` 不变。
- **更多箱子（Iron Chests）在 26.3 暂缺**：该模组目前没有 26.3 版本，其自带的 `~26.2` 版本约束会让加载器直接拒绝启动开发环境，因此只把它从**开发期**依赖里移除（它从来不在发布产物里，也不在 `depends` 里声明）。它只是可选兼容：装了会像 1.1.3 那样照常索引与整理，不装则相关方块不存在。
- **原版世界生成核心有改动**（单精度噪声），本模组不依赖世界生成，无需改动。

## ⚠️ 升级提示

- **世界存档升级不可逆**：26.3 的 `DataVersion` 从 4903 升到 5023，数据包 / 资源包格式从 107.1 / 88 跳到 121.0 / 97.1。存档一旦在 26.3 里打开并保存，就**无法再用 26.2 打开**。升级前请先整目录备份 `saves/`。
- **区块不会重生成**：已经探索过的区域保持原样，只有新探索的区块按 26.3 的新算法生成，在探索边界上可能出现地形接缝——这是版本升级的固有现象，与模组无关。
- **服务端与客户端都要换 1.1.4**：本模组是双端内容，混用 1.1.3/1.1.4 会因 `minecraft` 约束不一致而加载失败。单机与局域网房主只需替换 jar。
- **更多箱子的方块与物品会消失**：如果 26.2 存档里用了更多箱子，升级到 26.3（且没装它的 26.3 版本）后这些方块会丢失，索引里对应的箱子条目也会随之减少。等它发布 26.3 版本后再把方块补回来，然后重新扫描一次仓库即可。
- **索引、配置、仓库定义、标签、权限、审计全部沿用**：本版没有改索引格式，正常情况下不需要重新扫描。开发过程中曾观察到索引容器数 29 → 27，确认就是上面那两个更多箱子。
- 升级后建议依次点一遍：进存档打开面板「概览」确认容器数与物品种类对得上 → 「物品」页搜索 → 「取货」页取一件并确认搬运工送到 → 「搬运工」页确认显示名与状态。
