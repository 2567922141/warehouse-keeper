# Warehouse Keeper v1.1.6

开源前审查修复版。这一版修掉「聊天栏指令开的界面一闪就没」等 1 个可见故障，并补上一批数据安全与性能问题，全部**不改变索引格式、配置文件与指令语法**。

| 可选依赖 | Carpet 26.3（安装后搬运工以可见人形出现；不装也能正常取货/整理） |

> 本版本**没有改动索引格式、配置文件与指令语法**：升级只需替换 jar，仓库定义、标签、权限、审计与索引都能沿用，不需要重新扫描。

## 🐛 问题修复

- **在聊天栏敲 `/warehousegui`（或 `/whg`）面板一闪就回游戏**：26.3 的原版聊天界面在回车提交后会自己执行 `Gui.setScreen(null)`（`ChatScreen.keyPressed` 里 `handleChatInput` → `closeOnSubmit` → `setScreen(null)`），而客户端指令的回调是在 `handleChatInput` 里**同步**跑的，于是刚打开的面板立刻被顶掉。现在客户端指令只登记一个「待打开」标记，等下一 tick 聊天界面关掉之后再开。**按 B 键打开面板一直正常**，本版修的是聊天栏指令这条路（语音包 `/warehousevoice` 同源问题在 `warehouse-keeper-voice-0.2.1.jar` 一并修掉）。

- **假人死亡或下单超时后，副手「表演道具」会掉成真物品**：搬运工为了看起来像在搬东西，会把 `carried.get(0)` 的一份**真实拷贝**举在副手。以前只有正常收尾路径会清副手：下单超时/假人被模组外的原因（`/player X kill`、被怪打死、掉虚空）弄死时，这份拷贝会作为掉落物留在世界上 —— 等于凭空多一份物品。现在 `finish()` 收尾一律先清副手，并新增死亡监听（`ServerLivingEntityEvents.ALLOW_DEATH`，触发点在 `LivingEntity#die` 开头、**早于掉落**）：假人一死就清空副手并把订单按「已取出的物品已放回仓库」失败收尾。

- **配置文件/索引读不动时被静默重建，下一次保存就把原文件覆盖掉**：`container-tags.json`、`bots.json`、`index.json` 解析失败或内容为空时以前只打一行日志就按空表继续，随后 `save()` 覆盖原文件，玩家再没有找回的机会。现在读取失败/内容为空时**先把原文件另存为 `<文件名>.bak`** 再继续（与 `players.json` 的 `.bad-<时间>` 做法同口径），并在回显/日志里说明备份位置。

- **`settings.json`、客户端偏好、`categories.json` 直接覆写目标文件**：写到一半崩溃或掉电会留下半截 JSON，下次启动整份设置读不回来。现在统一改成「先写 `.tmp` 再原子替换」（`WorldStore.writeAtomic`），失败时删掉临时文件并保留原文件。

- **整理与巡检会为读箱子强行加载区块**：`Scanner.mapOf`、`getHeight`、`getBlockState` 这类读取在区块未加载时会把它顺手加载起来。整理是每 tick 轮着扫所有箱子的，于是玩家跑去没去过的地图时，模组会替他强载一堆区块（内存与卡顿）。现在整理、值守点计算、指纹巡检都先问一句 `isLoaded`（它本身不加载任何东西），没加载就这一轮跳过、下次再看。

- **索引/配置落盘占用服务端 tick**：大索引的 JSON 序列化与写盘以前在服务端 tick 线程同步做，保存一次就卡一下。现在序列化与写文件交给一个后台单线程（tick 线程只负责把索引抄成可落盘的 DTO）；**关服与 `/warehouse save` 仍是「当场写完再回话」**，不会因为异步而丢最后一次保存。

- **仓库名里带引号或反斜杠时被客户端改写**：服务端的 `NameArgument` 走 Brigadier 的 `readQuotedString()`，引号里认 `\"` 与 `\\`，所以 `a"b` 和 `ab` 是**两个**仓库。客户端以前把 `"` 和 `\` 直接剥掉、且只按空格决定加不加引号，于是名字里同时带引号和空格时整条指令会被拆成两半，删除/合并/扩建可能打到另一个仓库上。现在客户端只剥控制字符，发送时按规则加引号并转义。

- **删除仓库后的提示没说标签的事**：索引与区域会清掉，但 `container-tags.json` 里的标签还留着（区域内箱子物理上还在）。回显现在补一句「区域内箱子的标签没动，需要的话用 `/warehouse tag prune` 清一遍」。

## ⬆️ 升级提示

- **替换即可**：删除 `mods/` 里的旧 `warehouse-keeper-*.jar`，换成 `warehouse-keeper-1.1.6.jar`。不要同时留下新旧两个 jar（同一模组 ID 会导致加载失败）。
- **服务端与客户端都要升到 1.1.6**：界面修复在客户端，副手/落盘/加载守卫在服务端。
- 仓库定义、标签、权限、审计与索引都在 `config/warehouse-keeper/` 下，原样沿用；本版**没有**改索引格式，不需要重新扫描。
- 语音取货附加包同步出 **0.2.1**（修 `/warehousevoice` 同款闪退），可与本版一起用。
- 升级后建议验证一次：① 聊天栏敲 `/warehousegui` 能开出面板并停住；② `/player <假人名> kill` 之后假人**没有**掉落物、订单按失败结束并提示「已取出的物品已放回仓库」；③ 大仓库执行 `/warehouse save` 时游戏不再明显卡顿。

## ⚠️ 已知限制

- 索引的后台保存失败只写日志（`后台保存索引失败: …`），不再主动弹给玩家；需要当面确认成败时用 `/warehouse save`。
- RCON/指令与面板的取货上限仍是 4096；超限与非法输入都明确拒绝，不静默截断。
- 更多箱子（Iron Chests）暂无 26.3 版本，26.3 上**尚未实测**（26.2 版本线正常）；存档里若用过它，其方块与物品在 26.3 会消失。
- 未安装 Carpet 时搬运工不可见，仅能通过指令与面板观察作业结果。
- 专用服务端在没有客户端连入时，指令输出中的物品名为英文。
